# Square Hole landing page

A one-screen static page for squarehole.fun: the logo animation, the name, the slogan "Different shapes. Same hole."
and the picture of the cube in the glowing hole, plus one short line ("Square Hole is in development.") and a small
"@squarehole_" link to the account on X. Nothing else: no scripts, no cookies, no analytics, no third-party requests,
and no other links out. It is dark in light and dark system settings alike, and with reduced motion the animation is a
still logo.

There is no build step. `public/` is the site as it is served. On our server, `infra/server/Caddyfile` serves it and
redirects the five aliases; `functions/_middleware.js` keeps the Cloudflare Pages redirect for existing deployments.

```
apps/landing/
  public/                 the site (deployed as is)
    index.html            the page
    404.html              served for unknown paths, status 404
    styles.css            all styles, including the animation
    _headers              security and cache headers (Cloudflare Pages)
    robots.txt            robots allowed
    art/                  the picture (AVIF, WebP, PNG fallback) and the 1200 x 630 link-preview card
    brand/                wordmark and mark from the brand kit (squarehole-branding f7d565a, unchanged)
    fonts/                Plus Jakarta Sans, latin subset (OFL-1.1, licence alongside)
    favicon.*, apple-touch-icon.png, icon-*.png, site.webmanifest
                          the brand kit's favicon set (logo/favicon, unchanged)
  functions/_middleware.js
                          Cloudflare Pages Functions: any host but squarehole.fun answers 301 to squarehole.fun
  test/                   vitest: the redirect for each host, the headers, the content rules, the one link out,
                          the weight budget
  scripts/art.sh          regenerates public/art from the approved picture (not needed to deploy)
  scripts/card.mjs        composes the link-preview card (lockup and slogan over the picture); called by art.sh
```

## The redirect rule (Cloudflare Pages)

| Request host | Answer |
|---|---|
| `squarehole.fun` | served |
| `www.squarehole.fun`, `squarehole.xyz`, `www.squarehole.xyz`, `squarehole.fit`, `www.squarehole.fit`, `squarehole.pages.dev`, any `*.squarehole.pages.dev` preview, any other host | `301` to `https://squarehole.fun` + the same path and query, `Cache-Control: public, max-age=86400` |
| `localhost`, `127.0.0.1`, `[::1]` | served, so `wrangler pages dev` works locally (Cloudflare never routes these names to the project) |

The target is built as `https://squarehole.fun` + path + query, so a path such as `//example.com` cannot turn into
another host. Preview deployments redirect too; look at a change locally (below) before deploying it.

Each extra domain only reaches the middleware once it is added to the Pages project as a custom domain (Workers &
Pages → squarehole → Custom domains), with its DNS on Cloudflare. Turn on "Always Use HTTPS" in each zone (SSL/TLS →
Edge Certificates) so plain-http requests are upgraded before they reach the page.

## Headers

`public/_headers` sets, for every file: a Content-Security-Policy that allows only same-origin pictures, styles, fonts
and the web manifest (`default-src 'none'`, no scripts at all, `frame-ancestors 'none'`, `base-uri 'none'`,
`form-action 'none'`), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, a
`Permissions-Policy` that turns off camera, microphone, location, payment and similar features,
`Cross-Origin-Opener-Policy: same-origin`, and `Strict-Transport-Security: max-age=86400` (one day, no
`includeSubDomains`, no `preload`; raise it once every domain serves HTTPS without trouble). Pictures, fonts and the
brand files are cached for a week.

Cloudflare's docs say `_headers` does not apply to responses generated by Functions, so the middleware sets the same
security headers on everything it serves. `test/site.test.js` fails if the two lists differ.

On our server Caddy sends exactly the same security policy, including on missing pages and the empty `/nft/*` 404.
It caches `/art/*`, `/fonts/*` and `/brand/*` for a week (`public, max-age=604800`); other files and ordinary 404s use
`no-cache` so browsers revalidate after a release. NFT rejections and alias redirects use `public, max-age=86400`.
Missing assets get the ordinary 404 policy, not a week's cache. `test/server.test.js` checks Caddy against `_headers`
and the middleware's exported custom-domain list; the middleware still redirects Pages previews and unknown hosts.

Keep the page free of `<script>`, `<style>` and `style="..."`: the policy blocks them, and the tests check for them.

## The one link out

The home page links to https://x.com/squarehole_ (DECISION-LOG F81 XK5: the site and the account vouch for each other
against look-alike accounts). It is a plain `<a href>` under the short line, `rel="me noopener"`, named
"@squarehole_ on X" for screen readers; the X glyph beside the handle is inline SVG, so nothing is loaded from X and
the Content-Security-Policy is unchanged (a link the visitor follows is a navigation, not a request the policy governs;
`Referrer-Policy: no-referrer` keeps the visit's origin from X). `test/site.test.js` allows exactly this one address,
once, as the `href` of an `<a>` on the home page; any other off-site address in any page, the stylesheet or the
manifest fails, including a second link to the account, the account in a `<link>`, a longer x.com path, `http:` or
another host such as Telegram or Discord (planted cases in the test). The 404 page links only home. A further link
(Telegram, say) needs the founder's go and a change to that test.

## Run it locally

Any static server on port 5389 shows the page (the redirect is covered by the tests, not by this):

```sh
python3 -m http.server 5389 --bind 127.0.0.1 --directory apps/landing/public
# open http://127.0.0.1:5389/
```

With wrangler, which also runs the middleware and applies `_headers`:

```sh
cd apps/landing && npx wrangler pages dev public --port 5389
```

## Deploy (our server)

Founder decision, 2026-10-12: serve the landing from the existing DigitalOcean droplet, alongside the indexer and card
service, without Pages Functions. Claude deploys after review; this ticket does not change the live server or DNS.
The six hosts are `squarehole.fun`, `www.squarehole.fun`, `squarehole.xyz`, `www.squarehole.xyz`, `squarehole.fit` and
`www.squarehole.fit`. Perform the Cloudflare cutover in this order:

1. In Workers & Pages → **squarehole** → Custom domains, remove all six hosts from the Pages project. This stops
   Pages from claiming their routing; changing DNS alone is insufficient. Expect a transition window until step 4.
2. In the three zones' DNS settings, replace the six hosts' old Pages CNAMEs with **proxied A records** to the droplet,
   currently **203.0.113.10** (confirm it is still the server address). Remove conflicting records for those hosts,
   including stale AAAA records: the droplet is IPv4 only. Keep the orange proxy enabled, **Always Use HTTPS** on,
   and the existing API-compatible SSL/TLS mode. Set Browser Cache TTL to **Respect existing headers**, and ensure
   Cache/Redirect Rules do not override the origin policy or redirect path/query. The origin allowlist stays unchanged.
3. From the reviewed, committed checkout, run `infra/server/ship.sh` (or `infra/server/ship.sh <commit>`).
   It archives `apps/landing/public`, builds the stack on the droplet, checks required landing files and runs
   `caddy validate` with the release's config and landing mounted before switching `current`. Caddy mounts the
   landing read-only at `/srv/landing`; no landing build or Node runtime is needed. Existing API/card routes keep
   their behavior. SSH configuration and the release/rollback procedure are in `docs/runbooks/server.md`.
4. Check from **outside the droplet**. `ship.sh` automatically runs the release's `smoke-landing.sh` from the caller's
   machine. It checks all six HTTPS hosts: home page and asset bytes, security/cache headers, the real 404 page,
   private Pages control files returning 404, empty NFT 404s, and 301s retaining encoded paths and queries. It fails
   on a mismatch; the release has already switched, so a failed check does **not** automatically roll it back.
   Allow for DNS/certificate issuance; after correcting a failed check, rerun
   `bash infra/server/smoke-landing.sh` from the checkout of that release. Also check
   `curl -fsS https://api.squarehole.fun/healthz` and `curl -fsS https://api.squarehole.fun/card/healthz`.
5. Once those checks pass, **delete the Pages project**, or **redeploy it with no Functions**. The test NFTs' fixed
   baseURI is `squarehole-7ua.pages.dev/nft/...`; moving custom domains does not stop those crawler requests from
   reaching Pages. To keep a static project, upload only `public/` from a separate staging directory with no
   `functions/` or `_worker.js`, and verify the new production deployment has no Functions. Do not run the legacy
   deployment command below from `apps/landing`: it would upload the middleware again. Confirm old preview deployments
   with Functions are retired too and crawler requests no longer add Functions invocations. Keep the repository's
   `functions/_middleware.js`; the founder decides about deleting files.

`squarehole.fun` serves `index.html` and static files; unknown paths serve `404.html` with status **404**. `/_headers`
and `/_routes.json` are deployment controls and are not served. `/nft` and `/nft/*` return an empty **404** directly
in Caddy. Every request to the five aliases, including NFT paths, first gets **301** to `https://squarehole.fun`
with the original path and query; the canonical host then rejects NFT paths. No Functions, indexer or card request
is involved in landing traffic.

TLS is the API's existing model: HTTP is served at the origin, HTTPS uses Caddy's automatic public certificates
(HTTP-01 through Cloudflare), and Cloudflare upgrades visitors. **DNS-only will not work with today's firewall**:
before a future change, arrange public access to 80/443 and certificate renewal, replace the Cloudflare-only origin
allowlist and its boot/install behavior, and enable origin HTTP-to-HTTPS redirects. See the ticket evidence for the
full sequence and the shared API impact. This cutover only removes the Pages/Functions dependency.

The smoke check keeps temporary response files for diagnosis. A rollback to a commit before SH-LANDING-SERVER also
removes landing support; after DNS cutover, use a release that includes this ticket or restore Pages routing first.

## Deploy (Cloudflare Pages, direct upload)

Legacy deployment procedure, retained for the founder; do not use it after the server cutover or for the
Functions-free deployment in step 5 above.

Needs a Cloudflare API token with the "Cloudflare Pages: Edit" permission in `CLOUDFLARE_API_TOKEN` (and
`CLOUDFLARE_ACCOUNT_ID` if the token can see more than one account).

Run wrangler **from `apps/landing`**: it reads Functions from `./functions` in the directory it is started in and
uploads every file of the directory it is given. So `wrangler pages deploy apps/landing --project-name squarehole` run
from the repository root would skip the middleware (no redirect) and publish this README and the tests. Deploy
`public/` from here instead:

```sh
cd apps/landing

# Once: create the project with main as its production branch.
npx wrangler pages project create squarehole --production-branch main

# Each deploy. --branch main makes it a production deployment; without it wrangler uses the current git branch
# (for example sh-landing) and the upload becomes a preview.
npx wrangler pages deploy public --project-name squarehole --branch main
```

Then add the custom domains (squarehole.fun first, then the ones in the redirect table) to the project.

**Set the project to fail open** (Workers & Pages → squarehole → Settings → Runtime → Fail open / closed → Fail open).
Because `functions/_middleware.js` sits at the root of `functions/`, every request becomes a Functions invocation, the
page's picture, stylesheet, font and icons included (Cloudflare: "once you add Functions on a Pages project, all
requests by default will invoke your Function"). Functions requests count toward the Workers Free plan's 100,000
requests a day (static files that invoke no Function are free and unlimited), so a busy day of roughly 17,000 to 20,000
first visits (5 or 6 requests each) can use it up. Past the limit, "Fail open" keeps serving the static files as if
there were no Function, with the `_headers` policy; "Fail closed" returns an error page instead, which would take the
whole site down. Cloudflare's docs do not say which one a new project starts with, so set it explicitly. With fail open,
the only thing that stops is the host redirect: the other hosts then show the page themselves until the limit resets at
midnight UTC, which is harmless.

**`public/_routes.json` keeps static files and `/nft/*` away from the middleware** (2026-10-12): the Sepolia test NFTs'
fixed baseURI points at this project (`squarehole-7ua.pages.dev/nft/…`, 11,000 tokens), and crawlers re-reading those
addresses used up the daily 100,000 Functions requests. Excluded paths are served as plain files (free, unlimited, with
`_headers`); only page requests run the host redirect. `test/routes.test.js` fails if a new static file is not excluded.

Optional: to keep the redirects from using Functions requests at all, redirect `www.squarehole.fun`, the `.xyz` and
the `.fit` domains with Redirect Rules (or Bulk Redirects) in their zones instead, `301` to `https://squarehole.fun`
with the path and query kept. The middleware stays as the fallback for anything that still reaches the project.

## Weight

First visit, as Chromium fetched it (uncompressed; HTML and CSS shrink further with Cloudflare's compression): about 71
KB on a wide screen at 1×, 92 KB at 2×, 72 KB on an upright tablet at 2×, 64 KB on a phone at 2× and 72 KB at 3×. The
PNG fallbacks (288 KB wide, 196 KB phone) only load in browsers without AVIF and WebP. The link-preview card (86 KB
JPEG) is fetched by link previews, not by visitors.

## Pictures

`public/art/` is made by `scripts/art.sh` from the approved 1600 × 400 picture
(`docs/design/misfits-v2/banner/final/`, sha256 `a8202b69…dd921afe`, copied unchanged as `stage-1600x400.png`) and its
2800 × 700 master from the same render (commit `ea7e6353`). The 2:1 picture (phones and upright screens) and the
link-preview card are cut from the centre between two shapes, so no shape is cut in half. The card also carries the
horizontal lockup and the slogan over the top-left sky, placed by `scripts/card.mjs` from `public/brand/` and the
self-hosted font with the brand kit's proportions, so a share that shows only the picture still names the site. Needs
ImageMagick 7, cwebp, avifenc, and for the card the installed workspace (Playwright's Chromium from `apps/web`).
