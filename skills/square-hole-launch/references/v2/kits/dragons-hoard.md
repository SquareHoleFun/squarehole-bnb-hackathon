# Dragon's Hoard (HOARD)

> Generated by `scripts/kit-references.mjs`; edit the guide there, then run `pnpm launch-skill:write`.

## Start from this kit

Use native Sepolia ETH, listing 0. The base settings and registry still carry the earlier raise. The founder must execute updateRaise(0, 0.1 ETH) before creating these examples, then refresh the listing, quote and salts. Do not rewrite a saved hash or silently treat the old raise as current.

1. Review public bindings with the integrator, then rebuild from the repository root: `node scripts/kits/bundle.mjs dragons-hoard` (add `--bindings PUBLIC_JSON` when needed). A build alone does not prove any address is deployed.
2. Use the settings file `examples/boxes/dragons-hoard/settings/dragons-hoard-boxspec-v2.json`. In Create on Sepolia, choose **Load settings** and select that file. This is the app download, not a skill draft or the registry JSON below.
3. Choose the listing for **SepETH** by verified chain and token address. Loading ETH listing 0 does not select a test token. Resolve every slot in build/inventory.json, refresh the listing raise, and recheck the seed and creator buy in their own units.
4. Compare name, ticker, contents, art mode, fees, deadline and pick fee with the recipe. Confirm the opening time (zero means next block), art rights and final overview. The founder signs; prepare offline Safe batches for a shop.

Payouts are claim-only. Registry ready means the recipe has a test life; it is not evidence of Sepolia deployment. Refresh mutable listings before Create. Keep monetary values as raw decimal strings.

Public example art can be served by the project node. New box collections become listable only after graduation and take-out; Test Junk and Bent Cans are the outside full sets for these shops. Videos use captions only.
