# starter cards, the site's files with two releases, and the box "Quick Deck" (QDECK) on the second release: create,
# load, graduate, a pick by hack-alice, a give by hack-alice after the ten minutes. For the step runner (run-steps2.sh),
# from the REPOSITORY ROOT of a quiet folder:
#   RPC=https://bsc-testnet-rpc.publicnode.com SOURCE_COMMIT=(the merged commit, 40 hex) LOGDIR=(a folder) \
#     bash run-steps2.sh hackathon/short-wait/commands.txt 1 11

# extras file; a line that needs it and finds it unset stops). NO comment line here starts with a digit after '# ':
# the runner would read it as a step. Every line reads everything else itself: from the
# chain, the committed files, or the files under .cache/short-wait that earlier lines wrote.
#
# WALLETS: hack-deployer 0x2EF9A78074bbf674bEA16f21154a30c821A3C576 sends steps 2 to 8 and pays the pick (it owns the
# four card collections and holds the tUSDC for the box); hack-alice 0x2908E3351ec8F20a8a6746773e42EA1D2FFb3c7F picks
# and gives (steps 9 and 11); hack-bob 0xc979F6Cb8902f56f76b926358dC451cBF8f310F0 only in a read (step 7's early give
# try, a call, no transaction). Password files ~/.secrets/hack-deployer.pass and ~/.secrets/hack-alice.pass (forge and
# cast read them; card-shop.mjs hands the folder to cast unread).
# COST at 0.1 gwei (fork replay; the record in hackathon/short-wait/replay/): release 31 transactions about 0.0087
# tBNB; listings 6 to 11 transactions about 0.0004; cards 16 about 0.0001; the box (create 2, load 20, graduate 4)
# about 0.001; pick 3 and give 2 together about 0.0001. Together about 0.0103 tBNB, with 50% added 0.0155: step 1 asks
# the deployer for at least 0.016 tBNB and alice for at least 0.002.
# TIME: the box's launch window ends about 384 s after its creation (step 8 waits it out in real time); gives open
# ten minutes after the creation block (step 10 waits for that, at most 15 minutes). End to end about 25 minutes.
# NOT AT THE SAME TIME: nothing else may send from hack-deployer or hack-alice while this file runs (step 2's guard
# compares the deployer's nonce with step 1's; forge's resume and card-shop.mjs's kept transactions assume their own
# nonces). Run it alone.
#
# THE FOLDER (quiet, e.g. ~/work/run2), on the machine:
#   1. seed it (hx run2 --seed) and sync the merged commit into it (hx run2 'true' from the checkout of that commit);
#   2. build the contracts the file and `check` read, in that folder (packages/contracts), as measured on a fresh seed
#      synced from this branch (hackathon/evidence/SH-300-contracts.md, "The run file"):
#        cd packages/contracts && FOUNDRY_LINT_LINT_ON_BUILD=false forge build
#   3. the build is the one `check` compares with: step 1's last check runs `check` against the FIRST release and must
#      refuse (its shop and validator are not this build's variants); step 2's check compares every part of the new
#      release with this folder's out/ (immutables and library links masked). A folder whose out/ is from another
#      commit makes step 2's check fail before anything later is sent.
#
# RECOVERY (each step can be run again by itself: run-steps2.sh (file) n n; the .cache/short-wait files are the run's
# memory: never delete them while a step is unfinished):
#   step 1 writes start-block.txt, start-nonce.txt and first-release.sha256 ONCE; a second run prints and keeps them.
#   step 2 (31 transactions) NEVER RUNS TWICE: its first line refuses when .cache/short-wait/release-broadcast.json
#     exists, when forge's record packages/contracts/broadcast/DeployCoreV2BnbShortWait.s.sol/97/run-latest.json exists,
#     or when the deployer's nonce is not step 1's. If it stopped, see how far it got:
#       echo $(( $(cast nonce 0x2EF9A78074bbf674bEA16f21154a30c821A3C576 --rpc-url "$RPC") - $(cat .cache/short-wait/start-nonce.txt) )) of 31 sent
#       jq '[.receipts[] | select(.status == "0x1")] | length' packages/contracts/broadcast/DeployCoreV2BnbShortWait.s.sol/97/run-latest.json
#     The factory is the LAST of the 31 (jq -r .returns.factory.value of that record, or the contractAddress of its
#     31st transaction). If 0 of 31 were sent: delete the record and the three step-1 files by their full paths and run
#     steps 1 and 2 again. If some but not all were sent: forge's resume from the repository root, then run step 2's
#     lines after the send by hand, in order (run-steps2.sh refuses step 2 now, as it should):
#       (cd packages/contracts && forge script script/bnb/DeployCoreV2BnbShortWait.s.sol:DeployCoreV2BnbShortWait --sig 'run(address,address,address,address,address)' $(jq -r .chain.poolManager.address deployments/core-v1/97.json) $(jq -r .chain.weth.address deployments/core-v1/97.json) $(jq -r .chain.randomness.address deployments/core-v1/97.json) $(jq -r '.releases[0].safes.fit.address' deployments/core-v1/97.json) $(jq -r '.releases[0].safes.platform.address' deployments/core-v1/97.json) --rpc-url "$RPC" --sender 0x2EF9A78074bbf674bEA16f21154a30c821A3C576 --broadcast --slow --legacy --with-gas-price 100000000 --unlocked --resume)

#   step 3 (listings) and step 4 (cards): run the step again: the scripts read the chain and send only what is missing

#     put an old file back from its .old- sibling if one exists, delete the siblings, then run step 5 again (it refuses
#     a manifest that already holds two releases). The repository changes only by the orchestrator's commit of the
#     three files after reading their diff.
#   steps 6 to 9 (the box): run the step again: card-shop.mjs keeps every transaction in
#     .cache/short-wait/qdeck-state.json before it is sent and never sends one twice; a finished step sends nothing.
